# TinyOTA Edge SDK

Partner-facing SDK for integrating TinyOTA firmware updates into MCU and embedded Linux devices. This SDK is designed to connect devices to the TinyOTA hosted platform.

- Website: [https://www.tinyota.xyz](https://www.tinyota.xyz)
- Service: Hosted firmware management, staged OTA rollout, and update monitoring for production devices

## Quick Start with AI (Recommended)

1. Clone the SDK and open the folder in your AI tool:

```bash
git clone https://github.com/TinyOta/tinyota-edge-sdk.git
cd tinyota-edge-sdk
```

   Claude Code reads `CLAUDE.md`, Codex and most agents read `AGENTS.md`,
   Copilot reads `.github/copilot-instructions.md`, Cursor reads
   `.cursor/rules/tinyota.mdc`. All four are the same text, generated from
   `docs/AI_CONTEXT.md` and checked against the headers in CI.

2. Pick your environment in [`examples/`](examples/) and paste the prompt
   from its README:

| Environment | Example |
|---|---|
| ESP32 + Arduino IDE / PlatformIO | [`examples/esp32-arduino`](examples/esp32-arduino) |
| ESP32 + ESP-IDF | [`examples/esp-idf`](examples/esp-idf) |
| nRF + Zephyr / nRF Connect SDK | [`examples/zephyr-nrf`](examples/zephyr-nrf) |
| Linux (Raspberry Pi, gateways) | [`examples/linux`](examples/linux) |
| STM32, RP2040, other MCUs | [`PORTING_GUIDE.md`](PORTING_GUIDE.md) |

The console at [tinyota.xyz/docs](https://tinyota.xyz/docs) builds the same
prompts with your API address, registration token and public key filled in.

What the AI should know up front:

- Device API base URL: `https://api.tinyota.xyz` (the console is `tinyota.xyz`)
- Register once per boot with the model's registration token, then send the
  returned `access_token` as a Bearer token.
- Embed the signing public key at build time; updates without a valid
  SHA-256 checksum and ECDSA signature are rejected.

## Quick Start Without AI

Use this path if you are not using an AI coding assistant.

1. Build and run the POSIX sample first.
2. Implement all required functions in `fota_hal.h`.
3. Implement all required platform seam functions in `fota_platform.h`.
4. Follow [`PORTING_GUIDE.md`](PORTING_GUIDE.md) for your target board.
5. Validate with [`docs/CONFORMANCE_CHECKLIST.md`](docs/CONFORMANCE_CHECKLIST.md).

## What You Receive

- Public headers in `include/`
- Source SDK build system (CMake)
- Optional POSIX sample validation program for local testing (`fota_sdk_sample`)
- Partner integration documents:
  - [`PORTING_GUIDE.md`](PORTING_GUIDE.md)
  - [`docs/HAL_CONTRACT.md`](docs/HAL_CONTRACT.md)
  - [`docs/CONFORMANCE_CHECKLIST.md`](docs/CONFORMANCE_CHECKLIST.md)
  - [`docs/SDK_PARTNER_DISTRIBUTION.md`](docs/SDK_PARTNER_DISTRIBUTION.md)
  - [`docs/AI_CONTEXT.md`](docs/AI_CONTEXT.md) (source of `AGENTS.md`, `CLAUDE.md` and the Copilot/Cursor rules)

## What You Implement

- `fota_hal.h`
  - flash read/write/erase
  - boot slot switch
  - reboot
  - stable hardware serial
- `fota_platform.h`
  - HTTP GET/POST
  - SHA-256
  - ECDSA verification
  - optional delta patch support

JSON helpers, `fota_register()` and `fota_report_status()` come from
`src/fota_common.c` and work on every port.

## Build the Partner Package

```bash
cmake -S . -B build -DFOTA_PLATFORM=posix
cmake --build build
cmake --install build --prefix ./dist
```

`dist/` is generated by the install step. It is the package tree you deliver to a partner, not a source folder stored in git.

Expected install output:

```text
dist/
├── include/fota/
├── lib/
├── bin/            # optional
└── share/          # optional docs/config metadata
```

## Validate on POSIX First

The POSIX reference implementation is useful for smoke-testing the SDK before MCU porting.

Dependencies for POSIX reference build:

- `libcurl`
- `OpenSSL`
- `bzip2`

Build the reference agent:

```bash
cmake -S . -B build -DFOTA_BUILD_AGENT=ON
cmake --build build --target fota_sdk_sample
```

## Integration Flow

1. Build and link `fota_sdk` into your firmware or device application.
2. Implement every required function from `fota_hal.h`.
3. Implement the required platform seam functions from `fota_platform.h`.
4. Use [`PORTING_GUIDE.md`](PORTING_GUIDE.md) to complete integration.
5. Verify against [`docs/CONFORMANCE_CHECKLIST.md`](docs/CONFORMANCE_CHECKLIST.md) before production rollout.

## Runtime Model

```text
IDLE -> CHECKING -> DOWNLOADING -> PATCHING -> VERIFYING -> SWITCHING -> REBOOT
```

Error conditions return the FSM to a recoverable idle path after reporting the failure.
